# Guidelines

How Volti is written and built. Each guideline is grounded in code that already exists; where the code disagrees, the guideline lists it under "Not yet following this" until it is fixed.

- [Error and warning messages](messages.md): what the musician reads when something didn't work, and what goes in the log.
- [Android design](android.md): window sizes, system bars, Back, keyboard and pedal input, accessibility, settings.
- [App quality](quality.md): lifecycle, performance, dependencies, permissions, privacy and backup.
- [Data and storage](data.md): what is kept where, marks, schema changes and migrations, the PDF store.
- [UX laws](ux-laws.md): the Laws of UX that apply to a reader on a music stand, as rules.
